## 修复 2：P0-TUTOR-01 + P0-TUTOR-03（提交 `27ccf57`）

**根因**：
- `_check_answer` 遇到空 `expected` 返回 `True`，导致空标答的步骤任意输入都判对（`P0-TUTOR-01`）。
- `_complete` 无条件 `session.mastery_achieved = True` + `mastery_update=0.3`，一路错答走完也算"掌握"（`P0-TUTOR-03`）。

**改动**（`backend/services/tutor_engine.py`）：
- `_check_answer`：`expected` 为空 → 返回 `False`，依赖 3-attempt stuck 分支给讲解。
- `_complete`：按 `completed = sum(status=="correct") / total` 三档：
  - 全对 → `mastery_achieved=True` / `+0.3` / 开启 `variant_suggested` + `feynman_available` / 原鼓励文案。
  - `ratio >= 0.6` → `False` / `+0.1` / 关闭变式 / "答对 N/M 步，还没完全掌握"。
  - `< 0.6` → `False` / `0.0` / 关闭变式 / "先别急着做变式，回到卡住的步骤把讲解看懂再来"。

**保留不动的语义**：
- 3 次错答后自动 `_advance` 到下一步（`_check_answer` 上一层的 stuck 流程）—— 用户旁批多次说 "跳过、给讲解、继续下一步" 是 MVP 陪练形态，不是 bug，只需切断"完成 = 掌握"的错误联动即可。

## 环境与操作要点（给下一 agent）

- **git 陷阱**：本沙箱 SID 与用户 SID 不同，需 `$env:GIT_CONFIG_NOSYSTEM=1; $env:GIT_CONFIG_COUNT=1; $env:GIT_CONFIG_KEY_0="safe.directory"; $env:GIT_CONFIG_VALUE_0="*"`，否则所有 git 命令报 dubious ownership。
- **行尾**：仓库里 python 文件是 **LF**。PowerShell here-string 会写 CRLF，改完后必须归一到 LF（`.Replace(CRLF, LF)`），否则 `git diff --stat` 里会假装是整文件重写。
- **中文 JSON body**：`--data-binary "@file"` + UTF-8 无 BOM 写盘；不要在 PS 里用带双引号的 `-d '{"a":"..."}'`，PS 会把里面的双引号吃掉，body 变成 `{}` 让 FastAPI 报 `json_invalid`。
