# 注册输入即时校验设计

## 目标

让用户在提交注册前就能知道用户名和密码是否符合要求，避免汉字用户名或短密码提交后只得到笼统的“注册失败”。

## 范围

- 仅收紧**新用户注册**的用户名规则；既有账户的登录不受影响。
- 注册用户名仅允许 3–32 位 ASCII 英文字母或数字（`A-Z`、`a-z`、`0-9`）。
- 注册密码长度为 8–128 位。
- 前端即时提示与后端兜底校验使用同一条文案和边界。

不改变显示姓名规则、登录用户名规则、管理员已有账户或既有用户数据。

## 交互

注册模式下：

1. 用户名输入框显示规则提示“用户名仅支持 3–32 位英文字母或数字”。
2. 一旦输入非字母数字字符（包括汉字、空格、下划线、连字符）或长度不在范围内，字段下方立即显示错误提示并标红。
3. 密码输入框显示“密码需为 8–128 位”；输入后立即显示长度错误或通过状态。
4. 显示姓名、用户名、密码任一项无效时，“注册并登录”按钮禁用；提交函数仍重复校验，防止键盘提交或未来 UI 修改绕过规则。
5. 网络请求失败或用户名已存在时继续显示服务端的明确错误消息。

登录模式保持现有交互，不以新注册规则阻止已有用户名登录。

## 实现边界

- 新增前端纯函数模块，导出用户名常量、错误文案和合法性判断；`LoginPage` 与提交前校验复用它。
- 后端新增共享用户名策略函数，`RegisterRequest` 复用它；错误消息与前端一致。
- 不为该需求引入新依赖或修改数据库结构。

## 验收

- `abc123`、3 位和 32 位字母数字用户名可注册。
- 汉字、空格、`_`、`-`、少于 3 位、多于 32 位用户名在输入时提示且不能提交；直接调用注册 API 也返回明确错误。
- 7 位或 129 位密码在输入时提示且不能提交；8 位和 128 位密码可通过。
- 已有登录流程不因新注册规则而改变。
- 后端注册测试、前端纯函数测试、类型检查和生产构建通过。
