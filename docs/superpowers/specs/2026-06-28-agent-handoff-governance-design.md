# Agent 交接与防走样机制设计

> 日期：2026-06-28
> 适用项目：MathMind v1.1
> 适用分支：`feat/real-question-baseline`
> 状态：已确认，待编写实施计划

## 1. 背景

项目将继续在同一台电脑、同一 Codex 环境中执行，但可能更换底层大模型。模型不能依赖当前会话记忆理解项目，必须从仓库中的权威文档恢复上下文，并受到明确的任务边界和验收门禁约束。

交接机制的目标不是让新 Agent 一次性完成全部计划，而是确保它每次只执行一个已批准任务，提交可核验的结果后停止，等待用户明确授权再继续。

## 2. 目标

交接完成后，新 Agent 必须能够：

1. 找到唯一、明确的恢复入口。
2. 按固定顺序读取产品方案、验收设计、执行计划和最新进度。
3. 准确识别当前只允许执行的任务。
4. 遵守不可自行修改的产品口径和技术边界。
5. 使用测试、审查和 Git 提交证明任务结果。
6. 每完成一个任务后强制停止，等待用户回复“继续”。

## 3. 交接载体

采用“仓库内交接包 + 启动指令”的方式。

### 3.1 `AGENTS.md`

放在功能工作树根目录，作为 Codex 进入项目后应优先读取的长期约束。内容包括：

- 权威文档的读取顺序。
- 当前分支和工作树要求。
- 不可变产品口径。
- 单任务执行门禁。
- TDD、测试、审查和 Git 要求。
- 前端 Chrome DevTools 验证要求。
- 禁止提前部署和计划外扩展。

### 3.2 `docs/AGENT_HANDOFF.md`

作为人工可读的单一交接入口，记录：

- 项目价值定位和 MVP 主闭环。
- 权威文档索引及冲突优先级。
- 当前阶段、已完成任务和精确恢复点。
- 当前任务的允许修改范围和待解决问题。
- 每任务执行协议。
- 任务完成报告模板。
- 偏离计划时的停止和升级规则。

### 3.3 启动指令

提供一段可以直接发给新 Agent 的短指令。启动指令只负责要求它进入指定工作树、读取交接文件并执行当前任务，不重复承载完整项目事实，避免提示词与仓库文档产生两个版本。

## 4. 权威信息层级

新 Agent 必须按以下顺序读取：

1. 根目录 `AGENTS.md`：执行规则和禁止事项。
2. `docs/AGENT_HANDOFF.md`：当前交接入口和任务断点。
3. `docs/PROJECT_STATUS.md`：最新项目进度和已验证事实。
4. `SPEC.md` v1.1：产品定位、范围和阶段方案。
5. `docs/superpowers/specs/2026-06-27-real-question-acceptance-baseline-design.md`：当前工作包的设计基准。
6. `docs/superpowers/plans/2026-06-27-real-question-acceptance-baseline.md`：逐任务实施步骤。

发生冲突时，执行规则按上述顺序处理；产品口径以 `SPEC.md` v1.1 为准，执行进度以 `docs/PROJECT_STATUS.md` 和交接文件中的最新 Git 证据为准。新 Agent 不得自行解决实质性冲突，必须停止并向用户报告。

## 5. 不可变产品口径

未经用户明确批准，新 Agent 不得修改以下内容：

- 产品定位是“错题资产管理 + 陪练教练”，首页价值表达是“把错题变成可追踪的学习资产”。
- 当前数据库中的 14 道题全部是开发测试数据，不能作为真实题验收证据。
- 真实验收题包含复杂公式、几何图或函数图，并可能由多张图片组成。
- 复习间隔固定为 `10 / 30 / 90 / 180` 天。
- 当前优先验证真实题闭环，不提前进行部署、搜索、班级、多用户扩展或计划外重构。
- 前端改动必须使用 Chrome DevTools 检查桌面端、移动端、控制台和网络请求。

## 6. 单任务执行门禁

每次用户授权“继续”只允许执行当前计划中的一个任务。

一个任务必须依次经过：

1. 读取当前任务要求和相关代码。
2. 检查工作树、分支和基线状态。
3. 按 TDD 先增加或调整失败测试。
4. 实现满足当前任务所需的最小改动。
5. 运行专项测试和受影响范围的完整测试。
6. 执行规格符合性审查。
7. 执行代码质量审查。
8. 修复审查中的阻断问题并重新验证。
9. 更新 `docs/PROJECT_STATUS.md` 和计划执行快照。
10. 创建独立 Git 提交。
11. 按固定模板报告结果并停止。

只有用户明确回复“继续”后，才能开始下一个任务。“测试通过”“审查通过”或 Agent 自己判断工作顺利，都不能替代用户授权。

## 8. 完成报告模板

每个任务结束时，新 Agent 必须报告：

```text
任务：
状态：完成 / 阻塞
本次修改：
专项测试：
完整测试：
规格审查：
质量审查：
Chrome DevTools 验证：不适用 / 验证结果
Git 提交：
剩余风险：
下一任务：
等待用户授权：是
```

任何验证未执行时必须明确写“未执行”和原因，不得使用“应该通过”等推测性表述。

## 9. 偏离与异常处理

出现以下情况时必须立即停止，不得自行扩大范围：

- 文档之间存在无法按优先级消解的矛盾。
- 当前分支、工作树或数据库副本与交接记录不一致。
- 完成当前任务必须修改下一个任务的范围。
- 真实题、人工基准或数学结论存在冲突。
- 测试失败原因与当前任务无关，且修复会引入额外功能。
- 用户的新指令会改变已确认的产品口径、验收标准或任务顺序。

停止后应报告：发现的事实、影响范围、可选处理方式和推荐方案，等待用户决定。

## 10. 验收标准

交接包完成时必须满足：

- 新 Agent 只需收到一段短启动指令即可找到全部上下文。
- `AGENTS.md` 和 `docs/AGENT_HANDOFF.md` 对当前任务、禁止事项和停止条件表述一致。
- 权威文档路径均存在，Git 分支和提交信息可核验。
- 明确写出“每完成一个任务必须停止并等待用户授权”。
- 明确写出当前只能继续任务 2，不能开始任务 3。
- 不复制或改写原实施计划中的任务细节，以链接和当前断点为主，避免形成并行版本。
- 交接文件通过占位符、路径、矛盾和范围自检。
