# MathMind 可持续学生产品设计

> 日期：2026-07-13
> 状态：已完成用户设计确认，待规格审阅
> 基线：`feat/real-question-baseline`

## 1. 目标与非目标

### 1.1 产品目标

MathMind 的核心不是拍照搜题或推广工具，而是帮助中学生把错题转化为可复习、可诊断、可追踪掌握的学习资产。学生主闭环为：

```text
注册登录 → 上传并校对题目 → 入库 → 分步导学 → 卡点诊断 → 定时复习 → 掌握度与图谱变化
```

第一期成熟可运营版本的成功标准：首次访问的学生无需人工协助，能够注册、录入一道真实题、完成一次导学，并在后续看到待复习任务和掌握变化。

### 1.2 非目标

- 不在本阶段实现排行榜、积分、奖励或强制分享。
- 不做班级、教师、家长完整端、复杂 BI 或短信验证。
- 不将分享功能置于学生学习链路之前。
- 不记录学生题目正文、密码、完整 API Key 或完整 IP 用于运营分析。

## 2. 学生体验与学习闭环

### 2.1 首页

首页只回答三个问题：

1. 今天做什么：展示待复习任务并可直接开始。
2. 哪里需要补：展示最近诊断得到的 1–3 个薄弱点，并可进入对应图谱节点。
3. 我有进步吗：展示本周完成量、掌握变化和连续学习情况。

### 2.2 入库、导学与诊断

- 题目可由本地 OCR、视觉模型或手动录入得到；所有自动结果均允许学生在入库前校对。
- 导学采用逐步提问。学生可回答、获得提示、查看讲解或跳过；失败不会阻塞保存或后续学习。
- 完成后保存困难步骤、提示次数、薄弱点和下一步建议。
- 引擎或模型失败时，明确提示并回退到人工输入/校对，不阻塞学生入库。

### 2.3 复习与掌握度

- 固定复习间隔保持为 10 / 30 / 90 / 180 天。
- 完成复习后，结果可靠写回掌握度记录和知识图谱状态。
- 图谱显示需要加强的节点与正在改善的节点；不承诺未实现的三层变式题生成。

## 3. 账户与隐私

### 3.1 公开账户

- 公开注册只需要唯一用户名和密码，不收集或验证手机号。
- 系统内部以不可变用户 ID 关联题库、会话、复习和运营事件。
- 学生可随时修改显示姓名；该名称不影响用户名登录、数据关联或管理员管理。
- 密码采用现代安全哈希保存；管理员仅能重置密码，不能查看密码。

### 3.2 最小必要运营数据

每次登录记录时间、用户 ID、登录结果、设备/浏览器概况和网络信息。网络信息只持久化脱敏网段、归属地和稳定指纹；管理员不能查看完整 IP。

每次题目分析记录运行来源、供应商/模型名、成功状态、耗时和错误类别。不得记录题目正文、提示词、密码或 API Key。

运营日志设定保留期并定期清理，防止 SQLite 无限制增长。

### 3.3 管理员能力

管理员后台包含四个职责明确的区域：

- 账户与安全：账户状态、登录概况、重置密码、停用账户和审计日志。
- 学习活跃度：注册、活跃、入库、导学与复习的匿名化汇总。
- 引擎健康度：本地 OCR、视觉模型和文本模型的调用量、成功率、耗时与错误趋势。
- 分享转化：访问、注册、首次入库、首次完成导学的汇总漏斗。

管理员操作必须写入审计日志。学生分享者只可查看自己的汇总结果，不能查看被邀请人的个人信息或学习内容。

## 4. 分享与轻量推广

### 4.1 分享方式

由于当前没有可用的微信公众号 AppSecret，本阶段不接入微信 JS-SDK。提供以下通用能力：

- 每位已登录用户拥有专属推广链接。
- 移动端优先调用浏览器/系统原生分享能力。
- 微信内提供一键复制的推广文案与链接，供用户粘贴给好友或朋友圈。

不在页面上暴露公众号 AppID 或任何密钥。

### 4.2 归因

专属链接记录：链接访问、注册、首次入库、首次完成导学。归因仅用于汇总统计与分享者个人汇总，不展示被邀请人的隐私数据。

注册、登录和分享访问均实施频率限制，以降低刷号、撞库和统计污染风险。

## 5. 稳定运营与部署

### 5.1 代码与配置

- 以 `feat/real-question-baseline` 作为正式开发基线；验收后合并回 `master`。
- 配置私有远程仓库；每次发布前创建版本标签。
- JWT 密钥、管理员初始密码、模型 Key 和生产 URL 仅从环境变量读取，不写入代码或 SQLite。
- 保持 FastAPI 托管前端静态文件的单端口部署方式，降低家庭/小团队维护成本。

### 5.2 数据保护

- 数据库结构变更使用可重复执行的迁移。
- 每日自动备份 SQLite，保留最近 7 天。
- 发布前创建数据库备份；提供并演练恢复到测试环境的流程。
- 代码发布失败时可回滚版本；数据库变更必须具有清晰的兼容或恢复策略。

### 5.3 质量门禁与可观测性

每次发布前必须执行：后端完整测试、前端类型检查与构建、关键 API 健康检查。学生端核心链路还需浏览器验收。

生产环境记录匿名化错误、接口耗时以及 OCR/模型成功率；管理后台显示趋势，但错误采集失败不能影响学生学习主链路。

## 6. 分期交付与验收

### 第一期：运营底座与账户安全

- 正式基线、远程备份、环境变量和数据库备份。
- 公开注册、显示姓名修改、密码重置、账户停用。
- 登录审计、脱敏网络信息和基础引擎运行日志。

验收：陌生学生可安全注册与登录；管理员可支持账户问题；数据库备份可恢复到测试环境。

### 第二期：学生学习闭环完善

- 今日待复习、最近诊断、掌握变化。
- 复习结果写回掌握度和知识图谱。
- 真实题入库、导学和异常回退的可理解性提升。

验收：学生可完成一次真实题闭环并看到后续复习与掌握反馈；现有真实题验收不回归。

### 第三期：轻量推广与运营看板

- 专属分享链接、复制微信文案与系统分享。
- 访问至首次学习的转化漏斗。
- 账户、学习活跃度、引擎健康度和审计看板。

验收：推广不干扰学习链路；管理员可定位账户、引擎与运营问题；分享者仅见个人汇总。

## 7. 范围约束

每期仅交付一个独立可用版本。进入下一期前，必须完成对应自动化测试、浏览器验收、备份恢复验证和至少一次真实用户试用。未经明确需求，不新增短信验证、复杂营销、家长/班级系统或新模型适配。
