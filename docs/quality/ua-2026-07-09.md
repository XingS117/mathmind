## UA-06 登录与数据隔离（2026-07-09 追补）

登录能力从"仅有 API 但前端不使用"升级为"业务全链路带 token + 数据按用户隔离"。

**证据（生产 URL 实测）**

| 项 | 请求 | 结果 |
|----|------|------|
| 游客身份 | `GET /api/v1/auth/me` | `{"id":"u_default","name":"游客",...}` |
| admin 登录 | `POST /api/v1/auth/login {"username":"admin","password":"admin123"}` | 200，返回 JWT（149 字符） |
| 带 token 身份 | `GET /api/v1/auth/me -H "Authorization: Bearer ..."` | `{"id":"u_admin","name":"管理员","role":"admin"}` |
| 游客 dashboard | `GET /api/v1/learn/dashboard`（无 token） | `total_questions=11`（seed + 之前 UA 题） |
| admin dashboard（未上传前） | 带 token | `total_questions=0` |
| admin 上传真题（RQ-05-2） | `analyze` 24.67s，`confirm` 6.48s | `q_f20fad0f5ebd`（属 `u_admin`） |
| admin dashboard（上传后） | 带 token | `total_questions=1` ✅ 仅显示自己的 |
| 游客 dashboard（同时刻） | 无 token | `total_questions=11` ✅ 未见到 admin 上传 |
| knowmap 隔离 | `GET /api/v1/knowmap/summary` | 游客只看 `u_default`；登录者看`自己 + u_default` |

**修复细节**

- `frontend/src/services/api.ts`：改造 apiFetch 统一封装，业务接口自动带 `Authorization: Bearer` 头；401 时清 token 回落游客模式。
- `frontend/src/App.tsx`：`/auth/me` 用 fetchMe；游客态显示黄色提示条"点击登录以把错题绑到自己账号"；登录后导航条右侧显示"退出"按钮。
- `backend/routers/knowmap.py`：新增 `_visible_questions`，游客只看 `u_default`，登录者看`自己 + u_default`；修复此前 `tree/summary/nodes/{id}/questions` 未按用户过滤的隐私泄露。
- `backend/routers/auth.py`：清理 4 行 DEBUG print。
- `backend/tests/test_auth_scoped_data.py`：TestClient 集成测试锁定 dashboard/history/me 在带 token vs 不带 token 时按用户隔离。
